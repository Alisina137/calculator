# Google Play Submission — حساب فارسی

Last reviewed: 2026-09-22

## Source-side readiness

The app is configured for:

- Expo SDK 57 / React Native 0.86
- Android target API 36 through Expo SDK 57
- package name: `com.alisina.hesabfarsi`
- app version: `1.0.0`
- Android version code: `1` with EAS auto-increment for production builds
- production Android App Bundle (AAB)
- internal-testing APK
- no account requirement
- no ads
- no paid features
- no analytics SDK
- no backend
- offline core functionality

## 1. Before building

Run:

```powershell
cd C:\projects\calculator
npm install
npm run verify:release
```

Expected:
- Expo dependencies compatible
- TypeScript passes
- all regression tests pass
- Expo Doctor has no blocking issue
- release PNG assets are generated under `assets/release`

Inspect:
- `assets/release/play-store-icon.png`
- `assets/release/play-feature-graphic.png`
- `assets/release/icon.png`
- `assets/release/splash-icon.png`

## 2. Build a real-device preview APK

Install/login to EAS if needed:

```powershell
npx eas-cli login
```

Build:

```powershell
npx eas-cli build --platform android --profile preview
```

Install the generated APK on a physical Android phone and complete `docs/DEVICE-TESTING.md`.

Do not rely on Expo Go for final splash/icon/release validation.

## 3. Build the Google Play AAB

After the physical-device pass:

```powershell
npx eas-cli build --platform android --profile production
```

The production profile is configured as `app-bundle`; upload the resulting `.aab` to Google Play.

## 4. Create the app in Play Console

Recommended values:

- App name: حساب فارسی
- Default language: Persian if available for your listing workflow; otherwise choose your preferred Play Console default and add Persian/Dari translations
- App or game: App
- Free or paid: Free
- Category: Tools

Package name must stay:
`com.alisina.hesabfarsi`

Treat the package name as permanent after the first Play upload.

## 8. Data safety

Based on the current source architecture:

- Does the app collect or share required user data? No
- Data shared with third parties: No
- Account creation: No
- Data deletion request mechanism: Not applicable for server data because there is no account/server storage
- Local calculation history can be deleted inside the app

Do not change these answers unless the production build later adds analytics, advertising, cloud sync, crash reporting that collects identifiers, accounts, or other network data.

Current product functionality does not require:
- location
- camera
- microphone
- contacts

Review the generated Play Console App Bundle permission list before production submission. If unexpected sensitive permissions appear, investigate before publishing.

## 12. Internal / closed test

Upload the production AAB or use EAS Submit.

For an internal submission profile:

```powershell
npx eas-cli submit --platform android --profile internal
```

If your Google Play personal developer account was created after 13 November 2023, Google currently requires a closed test with at least 12 opted-in testers continuously for 14 days before you can apply for production access.

## 13. Production

When the account is eligible for production:

```powershell
npx eas-cli submit --platform android --profile production
```

Alternatively upload the AAB manually in Play Console.
